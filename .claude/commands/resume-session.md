# Resume Session - セッション状態の復元

新規セッション（または `claude -r` で選んだセッション）で前回の続きから再開するための入口。**記録と現実（git・ロック）を突き合わせ、食い違いを報告してから**再開する。

> クラッシュ復旧の正規手順: 同じフォルダで `claude -r`（一覧から選ぶ）か新規セッション → `/resume-session`。`--continue` は使わない（この環境ではバグ状態を引き継ぐことがある）。

## Usage
```
/resume-session
```

## Process

### 1. 記録を読む
- `{tasks-dir}/session-state.md`（ルーティングは session-persistence.md。SessionStart フックが注入済みなら再読不要）
- 当日（必要なら前日）の `journal/YYYY-MM/DD.md` の末尾 — 直近セッションの機械行とレポート節
- SessionStart の注入に「レポート未生成セッション」の警告があれば、その ID の journal 区間も読む

### 2. 現実と突き合わせる（食い違いは黙って直さず、報告する）
| 確認 | コマンド / 参照 | 見るもの |
|---|---|---|
| ブランチ | `git branch --show-current` | session-state の記載と一致するか |
| 未コミット変更 | `git status --porcelain` | 記録に無い変更ファイルは無いか（並走セッションの痕跡の可能性 — 触らず報告） |
| 最新コミット | `git log -1 --oneline` | 記録の SHA と繋がっているか |
| ロック | SessionStart 注入の 🔒/🔓 行 | locked なら slug と、作業がその範囲内かを確認 |

### 3. 報告して待つ
以下を平易な日本語で報告し、**ユーザーの指示を待つ**（勝手に作業を始めない）:
1. 現在地（ブランチ・最新SHA・ロック状態）
2. 前回の到達点（session-state の START HERE ＋ レポートの「次にやること」）
3. 記録と現実の食い違い（あれば。無ければ「一致」）
4. 推奨する次の一手（1行）

レポート未生成の過去セッションが検知されている場合は「/save-session 補完 を先に実行するか」も選択肢として提示する。
