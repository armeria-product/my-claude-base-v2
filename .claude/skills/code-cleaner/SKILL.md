# Code Cleaner — Removing Unnecessary Code (AI slop removal)

Remove redundant code (slop) generated by AI without introducing regressions.

## Usage
```
/code-cleaner [target path or scope]
```

## What is "Slop"?
Unnecessary code that AI tends to generate:
- Unused imports, variables, and functions
- Excessive type annotations (explicitly stating obvious types)
- Unnecessary try-catch (defensive error handling for internal code)
- Redundant comments (merely restating the code)
- Over-abstraction (helper functions used only once)
- Unnecessary null checks (places where null is impossible)
- Excessive logging
- Unused feature flags

## Process

### Phase 1: Protect (defend first)
- Run existing tests to record the current state
- If there are no tests, take a snapshot of important behavior
- **Establish a baseline that guarantees behavior does not change**

### Phase 2: Classify
Scan the target code and classify the slop:
```
DEAD_CODE: unreachable or unused code
DUPLICATE: duplicated logic
OVER_ABSTRACTION: unnecessary abstraction layers
DEFENSIVE_EXCESS: unnecessary defensive coding
COMMENT_NOISE: comments that merely restate the code
```

### Phase 3: Clean (one type per pass)
- **Remove only one type of slop per pass**
- Run tests after each pass
- Test failure → revert immediately and skip that pass

### Phase 4: Verify
- Re-run all tests
- Check the diff (deletions only, no additions)
- Confirm with the verifier agent that behavior has not changed

## Output
```markdown
## Slop Clean Report

### Removed
- [X] Dead code: N lines removed (files: ...)
- [X] Duplicate logic: N instances consolidated
- [X] Comment noise: N comments removed

### Kept (intentional)
- [reason why something that looks like slop was kept]

### Skipped (would break tests)
- [what couldn't be safely removed]

### Stats
- Lines before: X
- Lines after: Y
- Reduction: Z%
```

## Rules
- **Deletions only**. A code-cleaner pass must not add code
- **Preserving behavior is absolute**. If a test fails, revert immediately
- Do not delete TODO / FIXME / HACK comments, or any comment a machine reads — by class, not just by example: colon-less `@word` directives (`@vitest-environment`, `@ts-expect-error`, `eslint-disable`, pragma comments) and any comment compiled into a generated artifact (OpenAPI descriptions, doc generators). When you can't tell, keep it
- When in doubt, keep the code. A false negative (leaving slop) is safer than a false positive (breaking code)
