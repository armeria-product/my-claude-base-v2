skill と agent の違い

skills/ は複数ステップのワークフロー定義、agents/ は1タスク1役割の実行者・レビュアー定義。CLAUDE.md §5.3「Agent Resolution Order」では、同じ意図に複数の解決先がマッチした場合、Skill（軽量・インライン）→ Agent（独立コンテキスト）→ Command（明示起動のワークフロー）の順に優先する。

skill は基本的に description の内容とマッチする状況で自動発動し（user-invocable: true のfrontmatterはユーザーが明示的にも起動できることを示す）、その中で agent を Task/Agent ツール経由で呼び出す、という構造。

agent の基本構造

各agent定義ファイル（.claude/agents/*.md）はfrontmatterと本文からなる。

  • name — agent名
  • description — どんな時に使うかの自然言語説明（他agent/skillからの呼び出し判断に使われる）
  • model — 通常はnative alias（fable / opus / sonnet / haiku / inherit）。planner / reviewer は opus を既定にし、.claude/.fable-status が ONのとき（CLAUDE.md §1.11のゲート）だけ呼び出し側が model: fable を明示する（明示値がfrontmatterより優先）。.claude/rules/agents.mdは例外としてclover relayのモデルid（claude-<alias>形式）も許すが、権威席では外部idを許可せず、通常agentでもrelay経由のセッションでしか成立しない。特定の1回だけ外部モデルへ振りたい場合は、per-spawn の RELAY-MODEL: マーカー（relay skill）の方が壊れにくい
  • tools（任意）— 使えるツールの制限。reviewer / verifier / explorer は Bash を読み取り・テスト実行のみに制限し、Write / Edit / NotebookEdit を禁止（唯一の例外は reviewer の敵対的変異検証で、明示的に用意された使い捨て worktree の中でのみ許される）
  • effort（任意）— 推論の深さ。planner と reviewer は max に固定（frontmatterのpinがモデルtierとは独立に効き、validate.mjsがこの固定を欠くとFAILにする）
tierとaliasの関係

CLAUDE.md §2の表がtier方針の唯一の正本。native aliasはモデルのバージョン番号を直接固定しない。とくに権威席では順位比較ではなく許可集合fable | opusを使い、Opusを通常値、Fableを§1.11ゲートがONの間だけの値として扱う。

外部モデルへのルーティング（relay）

native名（fable/opus/sonnet/haiku/inherit）以外のモデル名が指定された場合だけ、relay skillの規約に従い、RELAY-MODEL:<alias>マーカーを先頭行に付けたworkerをspawnする。native Fable は relay に依存せず外部aliasへ変換しない。このマーカー便には独立した2つの関門がある。(1) CLAUDE.md §1.8のON/OFFゲート ―― OFFなら外部モデルは一切呼ばれない。(2) relay-required-agent.jsによるdescription必須化 ―― マーカーで外部モデルを指定した起動は、ゲートがONでもOFFでも常に、dispatchのdescriptionにそのaliasの文字列を含めないと拒否される。ユーザーの画面にも機械ジャーナルにも残るのはdescriptionだけで、プロンプト本文や実際に使うモデル名は表示されないため。前段のfrontmatterにclover idを直接固定するroute（legacy）はこのdescription必須化の対象外 ―― 呼び出しごとの宣言ではなく、agent定義に静的に効く設定だから。ゲートがONでも、実際にこのセッション自身がrelay経由で動いているとは限らない点に注意（サーバーが起動しているだけの場合がある）。

エイリアス一覧はここには複製しない ―― clover/models.jsonを直接参照するのが正本で、既定（先頭エントリ）が既定の外部co-reviewerに使われる。参考までに執筆時点（2026-08-03）の先頭エントリはgpt-5.6-sol（via codex, effort: xhigh）だが、一覧そのものは頻繁に更新され得るため常にmodels.json側を見る。

未知のalias名を指定された場合は、標準tierへ黙って切り替えず、必ずユーザーに確認する。alias名は「opus」「sonnet」「haiku」「fable」で始めてはならない（claude-<alias>という実IDが本物のClaudeモデル名と衝突するのを防ぐための命名規則）。

native Fable と外部モデルを混同しない

現在のFableはClaude Codeが直接受け取るnativeモデル名で、cloverの外部aliasではない。権威席の通常構成はOpus×2。.claude/.fable-statusがONのとき（CLAUDE.md §1.11）だけ両席を明示model: fableでFable×2として動かし、混在・無言切替・下位モデルへの降格はしない。Opusの起動に失敗した場合は報告して止め、Fableへの無言切替はしない。外部co-reviewerは別の第3席であり、この規約を置き換えない。fableで始まるclover aliasは禁止のままにして、native名との衝突を防ぐ。
