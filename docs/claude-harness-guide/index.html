対象 .claude/ 一式・CLAUDE.md ページ構成 本ページ＋5ページ 更新 2026-07-30 最新化済み

このガイドについて

ここで説明しているのは、CLAUDE.md と .claude/ 配下（agents / skills / rules / hooks / scripts / clover）が組み合わさってできている運用の仕組みそのもの。「指揮者(conductor)」であるメインセッションが作業役のエージェントに仕事を渡し、品質ゲートを通し、結果を tasks/ に記録する——という一連の流れを、初めて触る人でも掴めるように整理している。

正本（一次情報）は常に CLAUDE.md と各ファイル自身。このガイドはそれを読みやすくまとめた副読本であり、内容に食い違いがあれば正本側が正しい。各ページの記述は、資料作成時点でリポジトリの現物（設定ファイル・エージェント定義・スキル定義）を突き合わせて検証している。

隣にある関連資料

設定値の一覧は settings-reference.html、PDF変換のセットアップ手順は weasyprint-setup.html を参照。どちらもこのガイドと同じ docs/ 配下にある。

おすすめの読む順番

  1. architecture.html — まず全体像を掴む指揮者/workerの分業、tierポリシー、ディレクトリの役割分担という「地図」を先に持っておくと、後のページが早く読める。
  2. lifecycle.html — 開発が実際にどう流れるか1件の依頼が計画・実装・レビュー・検証・記録へとどう流れていくかを、時系列で追う。
  3. skills-agents.html — 個々の部品に降りる全体像で触れたスキル・エージェントそれぞれの詳細（発動条件・入出力・frontmatter）を確認する。
  4. quality-checks.html — 品質ゲートの中身quality-loopの審査サイクルや自己完結性チェックなど、「なぜ通った/落ちたか」を判断する仕組みを深掘りする。
  5. operations-reference.html — 困った時の辞書としてここまでで全体は掴めているはずなので、以降は必要になった時に参照する運用リファレンスとして手元に置く。
