WeasyPrint セットアップガイド（HTML → PDF 変換）

document-author が作る自己完結HTMLを、実ファイルのPDFとして書き出したいときだけ必要になる、一度きりの導入手順。

対象 html2pdf.mjs（WeasyPrint） 所要時間 初回のみ 20〜30分 更新 2026-07-30
結論

PDF変換はフェイルオープン設計 ―― WeasyPrintが入っていなくても html2pdf.mjs は失敗せず、PDF生成をスキップしてHTMLをそのまま残す。だから普段は何もインストールしなくていい。実際にPDFファイルが欲しくなったときだけ、この先の手順でWeasyPrintを入れる。

概要

document-author が作る自己完結HTMLを、実際のPDFファイルに変換するコマンドは次の1本だけ。

node .claude/scripts/html2pdf.mjs <in.html> <out.pdf>

内部では WeasyPrint（Python製）を呼び出してHTML/CSSをPDFにレンダリングしている。このガイドは、新しいマシンにこのリポジトリをクローンした直後にPDFエクスポートを有効化するための手順で、上のコマンドを実行してPDFが出てこない（スキップ通知が出る）ときに読む想定。

WeasyPrint を使う理由

  • Python製の HTML/CSS → PDF 変換ツール。CSS Paged Media（@page、改ページ、余白）への対応がしっかりしていて、このリポジトリの印刷CSS（break-inside: avoid など）がそのまま活きる。
  • ヘッドレスブラウザを使わないぶん出力が軽い。
  • トレードオフ: Windowsでは Pango/GLib のネイティブライブラリが要る（pip install だけでは動かない）。この一度きりの手順を次章で行う。

Windows 11 でのインストール

  1. MSYS2 をインストール（Pangoのネイティブライブラリを入れるための土台） 
    winget install MSYS2.MSYS2

    または msys2.org からインストーラーを落としてもよい。

  2. Pango をインストール ―― 「MSYS2 MinGW 64-bit」シェルを開いて実行: 
    pacman -S mingw-w64-x86_64-pango
  3. DLLの場所をWeasyPrintに伝える（PowerShell、セッションをまたいで恒久設定）: 
    setx WEASYPRINT_DLL_DIRECTORIES "C:\msys64\mingw64\bin"

    C:\msys64\mingw64\bin をシステムPATHの先頭にも足しておく（他のPango/GTK系DLL、たとえばTesseract-OCRのインストールより前に来るようにして、DLLの衝突を避ける）。設定後はターミナルを開き直す。

  4. WeasyPrint本体をインストール（Python 3.9以上）: 
    python -m pip install weasyprint
  5. 動作確認: 
    python -c "import weasyprint; print('weasyprint OK')"

    これがそのまま html2pdf.mjs が使っている判定と同じ。スクリプトは python → python3 → py の順に候補を試し、最初に import weasyprint が通ったコマンドをそのまま使う。複数のPythonを入れている場合、どれか1つで通ればよい（全部に入れる必要はない）。

Linux / macOS（参考）

WeasyPrintのネイティブ依存はシステムのパッケージマネージャで入るため、MSYS2のような橋渡しは不要。

  • Debian/Ubuntu: 
    sudo apt install python3-pip libpango-1.0-0 libpangocairo-1.0-0
pip install weasyprint
  • macOS（Homebrew）: 
    brew install pango
pip install weasyprint

使い方

node .claude/scripts/html2pdf.mjs report.html report.pdf

入力と出力は別のパスである必要がある（同じパスを渡すとその場でエラー終了する）。挙動は次の6パターン。

フェイルオープンの意味

WeasyPrint関連の失敗はすべて終了コード0で、呼び出し元のワークフローを止めない設計になっている。「PDFが出てこない」こと自体はエラー扱いではなく、コンソールに出るメッセージ（このページへの案内）を見て、必要なら導入すればいい。

日本語フォント

Windowsには Yu Gothic / Meiryo が標準で入っていて、document-author のシステムフォントスタックは最初からこれらを対象にしている。追加設定なしで日本語はそのまま描画される。

マシンをまたいで見た目を完全に揃えたい場合だけ、フォントをHTMLに埋め込む方法がある。ただし埋め込み方によって自己完結性の扱いが変わる。

フォント埋め込みの2通りと CLAUDE.md §10 自己完結性への影響
方法§10 自己完結性備考
別ファイルへの url(./fonts/xxx.otf)NG（外部ファイル依存）PDF専用の使い捨てビルドでのみ許容。閲覧用の単一HTML成果物には使わない
フォントを base64 の data: URIとして同じHTML内に埋め込むOK（外部参照なし）ファイルが数MB単位で膨らむ。日本語フォントは文字数が多く軽い部分集合化がしづらいので既定では非採用

local() はマシンにインストール済みのフォント名に依存するため、環境ごとに結果が変わりやすく、Windows上ではあてにしない。

トラブルシューティング

cannot load library 'libpango…'

手順2または3が未完了。pacman -S mingw-w64-x86_64-pango を実行済みか、WEASYPRINT_DLL_DIRECTORIES とPATHが C:\msys64\mingw64\bin を指しているかを確認し、ターミナルを開き直す。

pip installしたのに毎回スキップになる

html2pdf.mjs は python → python3 → py の順に試し、最初に import weasyprint が通ったものだけを使う。pip install した先とこの3つのコマンドが指す実体が食い違っていると検出できない。where python ／ where python3 ／ where py（Windows）で実体を確認し、weasyprintを入れたPythonと一致させる。

大きなボックスのまわりでページが白紙になる

break-inside: avoid を指定したコールアウトやテーブルが1ページに収まっていない。該当要素を1ページ以内の分量に削る（document-author のチェックリストがすでにこれを求めている）。
