設定リファレンス

Claude Code settings.json 完全リファレンス（日本語版）

Claude Code の設定ファイル（settings.json）に書けることを、公式ドキュメント（2026-07-30時点、Claude Code v2.1.219系）にもとづいて1つにまとめたリファレンス。設定は置き場所ごとに6段階（コマンドライン引数 > 組織管理設定 > ローカル設定 > プロジェクト設定 > ユーザー設定 > 組み込みの既定値）の優先順位で重なり、パーミッション（許可・拒否のルール）などの一部の項目は全ファイルの内容を足し合わせる特別な扱いになる。設定できる項目の一覧・権限ルールの書き方・hook（操作の前後に自動で差し込む小さな処理）の一覧・環境変数・CLAUDE.md やスキルなど周辺設定の置き場所を順に説明し、最後に2026年に入ってからの主な変更点をまとめる。

対象Claude Code v2.1.219 系 出典検証日2026-07-30 前版2026-04-24 版の全面更新 最新化済み
読み方

本文の内容は原則すべて公式ドキュメント（code.claude.com/docs）に基づく。例外的に「非推奨・名称変更」の扱いになっている項目だけ、後述の「非推奨・名称変更があったもの」の節でバッジ付きで示す（非推奨 = もう使わない方がいい、変更あり = 挙動や呼び方が変わった）。Managed設定（組織のIT管理者だけが設定できる項目）には Managed専用 の印を付ける。

設定ファイルの場所と優先順位

settings.json は置き場所によって効く範囲が違う4種類のファイルがあり、同じキーを複数のファイルに書いた場合は優先順位の高い方が勝つ（一部は例外的に足し合わされる。次項参照）。

設定ファイルの置き場所
スコープファイルパス効く範囲
ユーザー~/.claude/settings.json全セッション・全ディレクトリ
プロジェクト.claude/settings.jsonリポジトリのルートとサブディレクトリ
ローカル/worktree.claude/settings.local.json単一の worktree・ディレクトリ限定（v2.1.211+: リポジトリルート直下のファイルが優先される）
Managed（組織管理）Linux/macOS: /etc/ClaudeCode/managed-settings.json
Windows: C:\Program Files\ClaudeCode\managed-settings.json		組織全体のポリシー。Anthropicのサーバから配布・キャッシュされ、読み込みに失敗すると起動そのものをブロックする（fail-closed）

優先順位（上ほど強い）

  1. コマンドライン引数（--permission-mode、--model、CLAUDE_CODE_EFFORT_LEVEL 環境変数など）
  2. Managed設定（Anthropicのサーバから配布される組織ポリシー）
  3. ローカル設定（.claude/settings.local.json、リポジトリルート基準）
  4. プロジェクト設定（.claude/settings.json）
  5. ユーザー設定（~/.claude/settings.json）
  6. 組み込みの既定値
注意

allowManagedPermissionRulesOnly のような、後述の「Managed設定専用のキー」の節に挙げるフィールドは、組織のIT管理者だけが設定できる特別な項目。これらのフィールドがコマンドライン引数の優先順位（この節の表で最上位）よりも常に強く効くのかどうかは未確認——今回参照した一次資料には明記がなく、同資料の優先順位表はコマンドライン引数を最上位に置いている。ロックダウン用途で使う場合は公式ドキュメントで挙動を確認すること。

マージのルール

  • permissions.allow / deny / ask のルールは全ファイルを跨いで連結される。「一番優先度の高いファイルだけが勝つ」のではない（denyがallowに優先するという挙動は一般に知られているが、今回参照した一次資料には明記がなく未確認）
  • allowedHttpHookUrls（HTTP hookのURL許可リスト）も同様にファイルを跨いで連結される
  • それ以外のほとんどのキーは「上書き」——一番優先順位の高いファイルの値がそのまま使われる
  • fallbackModel は連結されない。一番優先順位の高いファイルが指定したチェーンがそのまま使われ、他ファイルの指定は無視される
  • v2.1.211より前は、Claude Codeを起動したディレクトリの settings.local.json が読まれていた。現在はリポジトリルート直下の .local ファイルが優先される
  • autoMode はv2.1.207以降、プロジェクト設定・ローカル設定からは読まれなくなった（それ以前はローカル設定も読まれていた）。使うなら ~/.claude/settings.json に書く

Managed設定専用のキー Managed専用

以下はサーバ管理設定（Managed settings）でのみ設定できる。組織のIT管理者が配布するもので、通常のユーザー/プロジェクト設定からは触れない。

  • allowAllClaudeAiMcps — Claude.aiコネクタを自動承認
  • allowedMcpServers / deniedMcpServers — 組織全体のMCPサーバ許可/拒否リスト
  • enforceAvailableModels — availableModels の値が無効ならfail-closed（v2.1.175+）
  • disableSideloadFlags — サイドロードフラグの使用を禁止（v2.1.193+）
  • claudeMd / claudeMdExcludes — 組織全体のCLAUDE.mdメモリ内容
  • channelsEnabled — Channels機能を有効化
  • browserExternalPageTools — "disabled" でブラウザツールをブロック
  • disableBrowserExternalNavigation — JSONのtrueでなければ効かない点に注意
  • disableMobileSimulatorTools、disableClaudeAiConnectors、allowManagedHooksOnly、allowManagedMcpServersOnly、allowManagedPermissionRulesOnly、blockedMarketplaces — 各種ロックダウン系フラグ

permissions ブロック

ツール呼び出しを自動で許可・拒否・確認するためのルールブロック。defaultMode で基本姿勢を決め、allow / deny / ask の配列で個別ルールを積み上げる。

{
  "permissions": {
    "defaultMode": "plan",
    "allow": [
      { "tool": "Bash", "input": { "command": "npm test" } },
      { "tool": "Read", "input": { "path": "src/**" } },
      { "tool": "WebFetch", "input": { "url": { "domain": "api.example.com" } } },
      { "tool": "Bash", "input": { "command": "python *" }, "permissionMode": "auto" }
    ],
    "deny": [
      { "tool": "Bash", "input": { "command": "rm -rf" } }
    ],
    "ask": [
      { "tool": "Bash", "input": { "command": "^git push" } }
    ],
    "additionalDirectories": ["/tmp/work", "$HOME/Documents"],
    "workDirectories": ["/var/app"]
  }
}
2つの書き方

上のようなオブジェクト形式のほかに、"Bash(npm test)"、"Read(src/**)" のようなコンパクトな文字列形式も引き続き使える。公式ドキュメントには両方の書き方が出てくる。

defaultMode の値

権限モード一覧（うち auto は2026年7月にGA〈正式リリース〉になったモード）
モード確認なしで動くこと向いている場面
default（別名 manual）読み込みのみ機密性の高い作業、使い始め
acceptEdits読み込み、ファイル編集、基本的なファイルシステムコマンドレビューしながらコードを反復する
plan読み込み＋分類器が承認したコマンド（自動モードが使える場合）変更する前にまず調べる
autoバックグラウンドの安全チェック付きで全部自動長時間タスク、確認疲れの軽減
dontAskallowで事前承認したツールだけ（それ以外は自動拒否）CI・ロックダウンされたスクリプト
bypassPermissions全部（削除操作へのサーキットブレーカー以外はチェックなし）隔離されたコンテナ/VM限定 ⚠️

ツールのマッチャーパターン

Bash(<正確なコマンド>)              // 完全一致: Bash(npm test)
Bash(npm *)                        // ワイルドカード一致
Bash(python|node|ruby)             // OR（いずれかにマッチ）
Bash(^git push)                    // 正規表現（先頭アンカー）
Read(<パスのglob>)                 // globパターン: Read(src/**)
Edit(src/**)                       // v2.1.214+: 単一セグメントの ** は <cwd>/src/** だけにマッチ。任意の深さには **/src/** と書く
WebFetch(domain:<ドメイン>)         // ドメインマッチャー。ワイルドカード: WebFetch(domain:*.example.com)
mcp__<server>__<tool>             // MCPツール: mcp__memory__store
mcp__<server>__.*                 // MCPワイルドカード（.* が必要）
Agent(*)                           // 任意のエージェントへの委譲

ルールフィールド

allow / deny / ask の各要素が持てるフィールド
フィールド型用途
toolstringツール名（必須）
inputobject入力パラメータのマッチャー（任意。省略すると全部にマッチ）
permissionModestringこのルールだけ権限モードを上書き（v2.1.214+）

特殊なルール

  • 読み取り専用のBashコマンドは、default / acceptEdits / plan の各モードで自動承認される
  • 保護されたパス（.git/、.claude/、.vscode/、.idea/、シェルのrcファイル、.npmrc、.gitconfigなど）は、bypassPermissions以外では自動承認されない
  • additionalDirectories — 作業ディレクトリの外で読み込み・編集を許可するパス（絶対パス、または$HOME/$VAR展開）
  • workDirectories — Bashを実行できる場所を制限する
  • 「常に許可」の選択はリポジトリルートに保存されるようになり、worktreeをまたいで有効（v2.1.211）
  • サブエージェントは親の権限モードを継承する。Taskツールのmodeパラメータは非推奨（v2.1.212）
このリポジトリの実例

このリポジトリの .claude/settings.json は次のように、機密ファイルの読み込みだけdenyで塞ぎつつ、それ以外はbypassPermissionsで確認なしに動かしている（信頼されたローカル環境向けの構成）。

"permissions": {
  "deny": [
    "Read(./.env)",
    "Read(./.env.*)",
    "Read(./**/.env)",
    "Read(./**/.env.*)",
    "Read(./**/*.pem)",
    "Read(./**/*.key)",
    "Read(./**/secrets/**)",
    "Read(~/.ssh/**)",
    "Read(~/.aws/**)"
  ],
  "defaultMode": "bypassPermissions",
  "additionalDirectories": []
}

hooks リファレンス

hookとは、Claude Codeの操作の前後に自動で差し込む小さな処理のこと。プロンプト送信・ツール実行・セッション開始などの「イベント」ごとに、実行するコマンドやHTTPエンドポイントを登録できる。

セッションSessionStart不可コンテキスト読み込み、監視ファイル設定、タイトル設定

フックの入力（stdin）

hookのcommandハンドラには、次のようなJSONがstdinで渡される（イベントごとに追加フィールドがある）。

{
  "session_id": "abc123...",
  "prompt_id": "550e8400-...",
  "transcript_path": "/path/to/transcript.jsonl",
  "cwd": "/home/user/my-project",
  "permission_mode": "default",
  "effort": { "level": "high" },
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "npm test" },
  "tool_use_id": "toolu_01ABC123..."
}

出力の仕組み

  • Exit code（commandハンドラ） — 0 = 成功（stdoutを有効なJSONとしてパース）。2 = ブロッキングエラー（stderrをClaudeに渡す）。それ以外 = 非ブロッキングエラー
  • HTTPハンドラ — 2xxで本文が空/テキスト = 成功（テキストはコンテキストとして注入）。2xxでJSON = 判定としてパース。非2xxまたはタイムアウト = 非ブロッキング

共通の出力フィールド

{
  "continue": false,
  "stopReason": "...",
  "suppressOutput": true,
  "systemMessage": "...",
  "terminalSequence": "..."
}

イベント別の判定フィールド

PreToolUse は次のような形で判定を返す。

{
  "hookSpecificOutput": {
    "permissionDecision": "deny|allow|ask|defer",
    "permissionDecisionReason": "...",
    "updatedInput": { "command": "safer-cmd" },
    "additionalContext": "..."
  }
}
  • PermissionRequest — {"hookSpecificOutput": {"decision": {"behavior": "allow", "updatedInput": {}}}}
  • PostToolUse — {"updatedToolOutput": "...", "additionalContext": "..."}
  • WorktreeCreate — {"hookSpecificOutput": {"worktreePath": "..."}}
  • SessionStart / SubagentStart — {"additionalContext": "...", "initialUserMessage": "...", "watchPaths": [...], "sessionTitle": "..."}

hookの実行方式
タイプ主な設定項目用途
commandargs（直接実行）またはshell形式スクリプトを実行。async、asyncRewake、shellのサブタイプあり

  • 完全一致の文字列／リスト（"a|b"）／アンカーなし正規表現（"log.*Error"）

  • パスのプレースホルダ: ${CLAUDE_PROJECT_DIR}、${CLAUDE_PLUGIN_ROOT}、${CLAUDE_PLUGIN_DATA}

関連する設定サーフェス（概要）

settings.json の周辺にある、他の設定の置き場所を簡単に触れておく。

  • エージェント（.claude/agents/*.md）: frontmatterに name、description、model（ティアalias/ID）、effort（low〜max）、tools（許可リスト）、permissionMode、isolation: worktree を書く
  • スキル（.claude/skills/<name>/SKILL.md）: frontmatterは name、description。スキルとコマンドは統合された（v2.1.146+）。動的なコンテキスト注入と同梱ファイルに対応
  • パス限定ルール（.claude/rules/*.md）: globパターンにマッチするファイルを操作するときに自動で読み込まれる
  • CLAUDE.md: プロジェクト全体の指示。毎セッション読み込まれる
  • 自動メモリ: 既定の保存先は ~/.claude/memory/{workspace}/。autoMemoryDirectoryでカスタマイズ可能
  • キーバインド（~/.claude/keybindings.json）: カスタムキー割り当て。/keybindings-help スキルが設定を手伝ってくれる
